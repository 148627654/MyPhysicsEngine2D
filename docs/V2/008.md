# V2-Day 8: 能量治理——休眠机制基础 (Sleep Logic - Part 1)

## 1. 目标
1.  **定义睡眠状态**：为 `Body` 引入睡眠相关的状态变量（能量阈值、时间累积）。
2.  **实现能量监控**：计算物体的“运动动能”，判定其是否处于准静止状态。
3.  **岛屿集体休眠**：在 `Island` 级别实现逻辑，当且仅当全岛物体都符合条件时，冻结整个岛屿。
4.  **性能飞跃**：实现“跳过解算”逻辑，对于睡眠中的岛屿，CPU 占用率为 0。
---
## 2. 核心概念

### A. 为什么要“全岛休眠”？
如果一个岛屿中有 99 个方块静止，但有 1 个方块在微微震动，那么这 100 个方块都不能休眠。
*   **一致性**：休眠必须以岛屿为单位。只要有一个物体是活跃的，它就可能通过碰撞传递能量给其他物体。
*   **效率**：一旦岛屿休眠，我们不仅跳过冲量解算，连重力积分、位置更新、甚至窄相碰撞检测都可以全部跳过。

### B. 能量阈值 (Energy Threshold)
我们不直接判断 $v == 0$，因为由于浮点数误差，物体几乎永远不会绝对静止。
*   **指标**：使用线速度的平方和角速度的平方 $E = v^2 + \omega^2$。
*   **睡眠计时器 (Sleep Timer)**：物体必须在一段时间（如 0.5 秒）内持续低于阈值，才能进入睡眠准备状态。

## 3. 必须实现的技术清单

### A. `Body` 状态扩展
- [x] **变量添加**：
    *   `bool m_isAwake`：是否处于清醒状态。
    *   `bool m_isSleepAllowed`：是否允许该物体休眠。
    *   `float m_sleepTimer`：当前物体处于低能量状态的持续时间。
- [x] **接口实现**：`SetAwake(bool)`, `IsAwake()`.

### B. `Island` 休眠判定逻辑
- [x] **更新计时器**：在 `Island::Solve` 中，遍历所有动态物体。
- [x] **状态检查**：
    1. 如果物体的 $v^2 + \omega^2 > \text{SleepThreshold}$，重置 `m_sleepTimer = 0`。
    2. 否则，`m_sleepTimer += dt`。
- [x] **全岛表决**：遍历岛屿，如果 **所有** 动态物体的 `m_sleepTimer >= k_timeToSleep`，则将岛屿内所有物体设为 `m_isAwake = false`。

### C. `World` 跳过逻辑
- [x] **执行拦截**：在 `World::BuildAndSolveIslands` 中，在调用 `island.Solve()` 之前，检查该岛屿是否符合休眠条件。
- [x] **宽相维护**：睡眠物体的 AABB 不会变化，因此无需触发 `MoveProxy`。

## 4. 技术实现细节 (Tips)

### 1. 阈值的经验值 (Golden Values)
*   **速度阈值**：$0.01 \sim 0.05$ 左右。
*   **时间阈值**：$0.5s$ 左右。过短会导致物体刚落地就“闪现”挂起，过长则浪费计算资源。

### 2. 静态物体的特殊性
静态物体不参与休眠计时（它们永远是静止的）。在岛屿表决时，只计算 `invMass > 0` 的动态物体。

### 3. 强制唤醒 (Manual Wakeup)
当你在代码中手动调用 `body->SetVelocity(...)` 或 `body->ApplyImpulse(...)` 时，必须自动调用 `SetAwake(true)` 并重置计时器，否则物体会像被“点穴”一样纹丝不动。

## 5. 今日验收测试 (Unit Test)

1.  **睡眠触发测试**：
    *   在地面上放置一个盒子，给予一个微小的初速度。
    *   **预期**：盒子在滑动一段距离后停止，几帧后 `IsAwake()` 返回 `false`。
2.  **岛屿一致性测试**：
    *   放置两个堆叠的盒子。手动让下面的盒子保持清醒，上面的盒子尝试休眠。
    *   **预期**：只要下面的盒子还在动，上面的盒子就永远不会进入睡眠状态（Timer 被重置）。
3.  **性能对比**：
    *   在场景中放置 200 个已经静止的方块。
    *   **预期**：控制台日志显示 `Island::Solve` 被跳过，Profiler 显示 CPU 占用率显著下降。
