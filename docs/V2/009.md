# V2-Day 9: 睡眠机制完善与结构变更响应 (Refined Sleeping & Structural Changes)

## 1. 目标
1.  **宽相剔除 (BroadPhase Culling)**：确保睡眠物体的 AABB 不会进入 `m_moveBuffer`，进一步降低宽相开销。
2.  **结构变更唤醒**：处理物体的添加、删除、类型修改等操作对睡眠状态的影响（例如：删除支撑物必须唤醒上方的物体）。
3.  **完善 API 设计**：提供标准的 `setAwake` 与状态查询接口，支持手动干预。
4.  **稳定性抛光**：优化能量计算公式，防止物体在极低速下的“永动”现象。

---

## 2. 核心概念

### A. 移动缓存剔除 (MoveBuffer Culling)
在 `World::Step` 的同步阶段，只有**清醒**的物体才会被 `MoveProxy`。
*   **意义**：动态树不需要为睡眠物体做任何更新。即使它们位移为 0，跳过 `MoveProxy` 调用也能省下大量的函数跳转和 AABB 包含判定。

### B. 结构性唤醒 (Structural Wake-up)
物理世界不仅通过“碰撞”唤醒，还通过“关系”唤醒：
*   **删除物体**：如果一个睡眠中的方块被删除了，它身上挂载的所有 `Contact` 对应的邻居必须立即唤醒，防止邻居悬浮在空中。
*   **修改类型**：将静态物体改为动态物体，或者移动静态物体，必须唤醒周边的所有睡眠物体。

## 3. 必须实现的技术清单

### A. `World::Step` 同步优化
- [x] **拦截同步**：修改 AABB 同步循环，增加 `if (!b->IsAwake()) continue;`。
- [x] **状态断言**：在同步前确保睡眠物体的速度确实为零。

### B. 邻居唤醒逻辑 (Neighbor Wake-up)
- [x] **删除唤醒**：在 `World::RemoveBody` 中，遍历该物体所有的 `ContactEdge`，手动调用 `edge->other->setAwake(true)`。
- [x] **添加检查**：新物体加入世界时，如果其 AABB 与睡眠物体重叠，是否需要立即唤醒？（通常由下一帧的宽相回调自然处理，但需确保逻辑闭环）。

### C. 状态机完善
- [ ] **`Body::SetType` 增强**：如果物体类型从 `Static` 变为 `Dynamic`，自动调用 `setAwake(true)`。
- [ ] **强制休眠接口**：实现 `ForceSleep()`，在特殊业务逻辑下强制冻结物体。

## 4. 技术实现细节 (Tips)

### 1. 速度“零容忍” (Velocity Clamping)
在 `IsLand::Solve` 中，当判定物体准备入睡时：
*   **技巧**：直接将 `velocity` 和 `angularVelocity` 强制设为 `(0,0)` 和 `0`。
*   **原因**：防止物体带着 $10^{-6}$ 级别的速度进入“逻辑睡眠”，这会导致在唤醒瞬间产生微小的位置跳变。

### 2. 删除物体时的链表安全
由于 `RemoveBody` 会导致 `Contact` 销毁：
*   **顺序**：先遍历 `ContactEdge` 唤醒邻居，再销毁 `Contact` 对象，最后从 `m_bodies` 移除。

### 3. 睡眠物体的受力处理
如果在代码中对一个睡眠物体调用 `ApplyForce`：
*   **逻辑**：`ApplyForce` 必须内部触发 `setAwake(true)`。否则力会被累加到 `m_force` 但物体永远不会动。

## 5. 今日验收测试 (Unit Test)

1.  **悬空唤醒测试**：
    *   搭建一个双层方块塔，等待它们全部入睡。
    *   手动调用 `world.RemoveBody(底座方块)`。
    *   **预期**：上方悬空的方块应瞬间被唤醒并自由落体，而不是停在半空中。
2.  **类型转换测试**：
    *   创建一个 `Static` 的平台支撑着几个睡眠中的方块。
    *   将该平台 `SetType(Dynamic)`。
    *   **预期**：平台由于重力下坠，上方的方块应同步被唤醒并跟随坠落。
3.  **零漂移压力测试**：
    *   放置 500 个方块并全部休眠，记录 1000 帧后的坐标。
    *   **预期**：坐标位移应精确为 0，且 `MoveProxy` 的调用计数器应为 0。
