# V2-Day 13: 持续碰撞检测 (CCD) 之 子步解算 (Sub-stepping)

## 1. 目标
1.  **实现时间回溯 (Time Backtracking)**：利用昨天算出的 $TOI (\alpha)$，将发生碰撞的物体强行推进到撞击发生的瞬间。
2.  **实现子步解算循环 (TOI Solving Loop)**：在一帧内处理多次撞击，确保高速物体即使经过多次反弹也不会穿墙。
3.  **物理拦截 (Physical Blocking)**：彻底解决子弹穿墙 Bug，让高速物体在撞击瞬间产生真实的反弹或停止。
4.  **最终集成**：将 CCD 系统完整嵌入 `World::Step` 流水线。

---

## 2. 核心概念

### A. 什么是子步解算 (Sub-stepping)？
*   **离散解算**：物体直接从 $t$ 跳到 $t+dt$。
*   **子步解算**：如果发现碰撞发生在 $t + 0.75dt$。
    1.  先让物体正常走完前 $75\%$ 的路程。
    2.  在那个精确的接触点停下，执行碰撞冲量解算（反弹）。
    3.  用剩余的 $25\%$ 时间和新速度继续走。

### B. 芝诺悖论预防 (Zeno's Paradox Prevention)
在极端情况下，物体可能在一帧内发生无数次微小碰撞。
*   **策略**：设定“最大子步数”（如 3 次）和“最小时间片”，防止系统陷入无限循环。

## 3. 必须实现的技术清单

### A. `World::SolveTOI` 函数
- [ ] **寻找最小 $\alpha$**：遍历所有 `Contact`，找出全场最早发生的碰撞点 $\alpha_{min}$。
- [ ] **同步位姿**：将涉及到的物体通过 `GetTransform(alpha_min)` 移动到撞击点。
- [ ] **微步冲量解算**：
    1.  对该 `Contact` 执行一次特殊的 `ImpulseSolver`。
    2.  更新物体的速度。
- [ ] **时间步截断**：将剩余时间标记为 $dt = dt \times (1 - \alpha_{min})$，继续查找下一个 TOI。

### B. `World::Step` 流程重组
- [ ] **集成顺序**：
    1.  执行离散模拟（原有的 `BuildAndSolveIslands`）。
    2.  执行 **CCD 专项解算**：针对标记为 `IsBullet` 且有 `m_toi < 1.0` 的物体进行子步迭代。

### C. 碰撞保护 (Slop Handling)
- [ ] **防粘连**：在回溯位置时，让物体停在距离障碍物 `Settings::LINEAR_SLOP` 的地方，而不是绝对的 0 距离，防止解算器下一帧报重叠。

## 4. 技术实现细节 (Tips)

### 1. 局部解算 vs 全局同步
*   **简单方案**：当发现 $\alpha_{min}$ 时，只移动发生碰撞的那两个物体，其他物体不动。
*   **严谨方案**：全场所有物体同步推进到 $\alpha_{min}$。
*   **建议**：V2 阶段建议采用**局部移动**。只处理子弹和它撞到的目标，性能开销最小且能解决 99% 的穿墙问题。

### 2. 速度反转 (Bounce)
在子步解算时，调用 `ImpulseSolver` 后，子弹的速度会立即反转。由于子步循环还在继续，下一轮迭代会自动检查反弹后的轨迹是否又撞到了其他东西。

### 3. `IsAwake` 联动
子步解算产生的撞击必须触发 `setAwake(true)`，确保睡眠中的物体被高速子弹“惊醒”。
