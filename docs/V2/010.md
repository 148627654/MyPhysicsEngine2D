# V2-Day 10: 唤醒触发器与预解算优化 (Wake-up Triggers & Pre-Solve)

## 1. 目标
1.  **唤醒传播 (Wake-up Propagation)**：完善由于关节（Joint）或外部脚本导致的链式唤醒逻辑。
2.  **实现“预解算” (Pre-Solve)**：将 `ImpulseSolver` 内部重复的数学计算（如 K 矩阵、有效质量）提取到循环外。
3.  **冲量热启动 (Warm Starting)**：正式应用 `Manifold` 中缓存的 `impulseN/T`，大幅提升高层堆叠的稳定性。
4.  **性能收官**：完成第 2 阶段（能量管理）的所有细节，确保引擎在静止状态下几乎不消耗 CPU。

---

## 2. 核心概念

### A. 冲量热启动 (Warm Starting)
*   **原理**：由于物理世界具有“时间连续性”，上一帧的碰撞冲量往往是这一帧最好的初始猜测值。
*   **实现**：在进入 `velocityIterations` 循环之前，先根据缓存的冲量对物体进行一次速度修正。这能让物体在接触地面的第一时刻就达到受力平衡，彻底消除“抖动”。

### B. 预解算 (Pre-calculation)
*   **优化点**：在冲量迭代中，`invMassSum + (rAn * rAn * invInertiaA) + ...` 这一长串分母在每一帧的 8 次迭代中都是**完全一样**的。
*   **方案**：在 `IsLand::Solve` 的开头，为每个 `Contact` 计算一次“有效质量（Effective Mass）”，并存入 `Contact` 或 `Manifold`。

## 3. 必须实现的技术清单

### A. `Contact::PreSolve` 函数
- [ ] **计算有效质量**：预计算法向和切向的 `massNormal` 和 `massTangent`（即原有公式的分母倒数）。
- [ ] **热启动应用**：根据 `m_manifold.impulseN/T` 立即调用 `bodyA->ApplyImpulse(...)`。

### B. `IsLand::Solve` 逻辑升级
- [ ] **新增预处理循环**：在迭代循环之前，遍历 `m_contacts` 调用 `PreSolve`。
- [ ] **解算器精简**：将 `ImpulseSolver` 修改为仅处理增量冲量的累加，不再重复计算 $rA, rB$ 等几何常数。

### C. 外部触发器 API (Triggers)
- [ ] **`World::WakeNeighbors`**：实现一个辅助函数，当某个物体被外部强行修改（如 UI 拖拽）时，唤醒与其接触的所有邻居。
- [ ] **`Body` 状态同步**：确保所有修改物理量的函数（如 `AddForce`）都能完美传播唤醒信号。

## 4. 技术实现细节 (Tips)

### 1. 有效质量的倒数
公式 $K = \frac{1}{m_A} + \frac{1}{m_B} + \frac{(r_A \times n)^2}{I_A} + \frac{(r_B \times n)^2}{I_B}$。
在 `PreSolve` 中直接存储 $1/K$，迭代时只需做一次乘法，省去了昂贵的除法运算。

### 2. 热启动的风险
**注意**：如果这一帧的碰撞点与上一帧偏移过大，缓存的冲量可能会导致物体“瞬移”。
*   **高级技巧**：在 `Contact::Update` 中对比新旧碰撞点的距离，如果偏移太大，清空缓存冲量。

### 3. 线程安全预警
如果你将来计划使用多线程，`PreSolve` 阶段是计算密集型的，非常适合并行化处理。
